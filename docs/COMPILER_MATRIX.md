# Real compiler compatibility checks

Enable the optional compiler matrix when configuring Beryl:

```sh
cmake -S . -B build-matrix -DCMAKE_BUILD_TYPE=Debug \
  -DCMAKE_C_FLAGS=-Werror -DBERYL_COMPILER_MATRIX=ON \
  -DBERYL_GCOBOL_EXECUTABLE=/usr/bin/gcobol-15
cmake --build build-matrix --parallel
ctest --test-dir build-matrix --output-on-failure
```

With GnuCOBOL available, this adds IBM and Micro Focus dialect profiles and
strict COBOL 85/2002/2014 profiles. Each vendor profile and GCC COBOL checks:

- Fixed SEQUENTIAL file bytes, golden results, archived replay and detection of
  a deliberately incorrect boundary result.
- 2,002 independent 25-byte records covering ASCII signed DISPLAY, scaled
  decimals and signed/unsigned odd/even packed decimal storage. Three directed
  vectors are followed by every integer from -999 through +999, with scaled
  and multiplied values computed independently in COBOL.
- A seeded corpus of 100 generated records, checked by COBOL NUMERIC predicates
  and echoed without any byte changes.
- A generated BY REFERENCE driver, including transformations, return status and
  extra-record rejection.

Strict standards profiles check golden output, replay and boundary regression
using the portable accounts fixtures. The other fixtures use vendor extensions
such as RETURN-CODE and COMP-3; they are not evidence of strict standard support.
IBM and Micro Focus dialect modes remain GnuCOBOL implementations, not validation
on those vendors' products.

`BERYL_GCOBOL_FLAGS` accepts extra compiler options for a nonstandard toolchain
layout. `BERYL_GNUCOBOL31_EXECUTABLE` and `BERYL_OPENCOBOL_EXECUTABLE` select
additional installed compilers. These optional paths never trigger downloads or
license activation. The compiler must have its matching headers, configuration
and runtime libraries available; do not mix different versions' libcob libraries.

For separate local installations, `BERYL_MATRIX_<profile>_ENVIRONMENT` accepts
semicolon-separated `NAME=value` assignments for compilation and execution.
The profiles are `gnu_312`, `opensource_cobol`, `gcobol`, `gnu_ibm`, `gnu_mf`,
`gnu_cobol85`, `gnu_cobol2002`, and `gnu_cobol2014`. This allows each compiler
to select its own `COB_CONFIG_DIR`, `COB_COPY_DIR`, `COB_CFLAGS`, `COB_LDFLAGS`
and `LD_LIBRARY_PATH`, including when the invoking shell has another version
configured. Empty values override inherited settings; supply the compiler's
required include/link flags when overriding its defaults.

## opensource COBOL and older GnuCOBOL

The additional native profiles use the same four integration suites as GCC
COBOL. The tested upstream releases are:

- [GnuCOBOL 3.1.2](https://ftp.gnu.org/gnu/gnucobol/gnucobol-3.1.2.tar.xz).
  It was built locally with GCC 15.2 using `CFLAGS=-std=gnu17`,
  `--without-db --without-curses` and a separate installation prefix.
- [opensource COBOL 1.5.2J UTF-8](https://github.com/opensourcecobol/opensource-cobol/tree/v1.5.2J-utf8),
  commit `8470e7cb754fcf9bebcf741fd60b8bee1c88eb3f`.
  Its compiler/runtime build used `-std=gnu17 -fcommon
  -Wno-implicit-function-declaration` with GMP/Berkeley DB headers and libraries.
  Its generated C also needs `-std=gnu17 -fcommon` on GCC 15; without `-fcommon`,
  linking the two-module callable driver fails on duplicate `cob_unifunc` symbols.
  This is a legacy toolchain requirement, not a change to the COBOL fixture.

These dependencies were installed in local prefixes. Their binaries are not
vendored or downloaded automatically by Beryl's build.

## Java-targeting COBOL 4J

Configure the Java profile with an installed compiler, Java runtime and runtime JAR:

```sh
cmake -S . -B build-matrix -DBERYL_COMPILER_MATRIX=ON \
  -DBERYL_COBOL4J_EXECUTABLE=/path/to/cobj \
  -DBERYL_JAVA_EXECUTABLE=/path/to/java \
  -DBERYL_COBOL4J_RUNTIME=/path/to/libcobj.jar \
  '-DBERYL_MATRIX_cobol4j_ENVIRONMENT=PATH=/path/to/jdk/bin:/usr/bin:/bin;CLASSPATH=/path/to/libcobj.jar'
```

Set `COB_CONFIG_DIR`/`COB_COPY_DIR` in that environment too if the invoking shell
has them configured for another compiler. The matrix compiles actual COBOL into
Java classes. Small C17 exec launchers use absolute class paths while leaving
Beryl's private working directory and resource limits in place. They are test
fixtures, not a new Beryl dependency or a general Java deployment adapter.

The tested release is [COBOL 4J 2.1.0-hotfix1](https://github.com/opensourcecobol/opensourcecobol4j/tree/v2.1.0-hotfix1),
commit `e71a28206a374c4fa096d8c2ae7f5a1e682ec1d4`, built with OpenJDK
21.0.12.1. The compiler/runtime were built from the tagged source with the
upstream `configure --enable-utf8`, `make` and `make install` workflow and a
separate prefix. The first upstream Gradle runtime build downloaded its normal
dependencies; no account was required.

The default generated Java main loses GOBACK's RETURN-CODE. The test profile
supplies a compiler configuration including `default.conf` and
`enable-program-status-register: yes`; its driver test requires the actual
process exit status to be 7, along with correct output bytes and extra-record
rejection. This setting is part of the tested configuration.

The JVM test launchers use `-Xms16m -Xmx64m -XX:+UseSerialGC
-XX:MaxMetaspaceSize=64m -XX:CompressedClassSpaceSize=16m
-XX:ReservedCodeCacheSize=32m -Xss256k -XX:ActiveProcessorCount=2` to fit Beryl's
existing 512 MiB virtual-address limit. A default JVM failed to start under that
limit. These settings are for the small integration fixtures, not a universal
heap configuration for arbitrary applications.

For ordinary Beryl runs, Java can be selected directly with `--exec` and repeated
`--arg` values for JVM options, the absolute class path and the generated class
name. Keep classes/JARs immutable across replay: Beryl hashes the selected
executable and input/output evidence, not every transitive runtime dependency.

Coverage and COPY preprocessing remain separate GnuCOBOL-specific adapters. The
matrix does not imply that those adapters support every compiler.

## IBM COBOL for Linux evaluation

The user-supplied official **IBM COBOL for Linux 1.2.0.9** evaluation is installed
at `/opt/ibm/cobol/1.2.0`, with its matching runtime under `/opt/ibm/cobol/rte`.
The earlier apparent expiration was resolved by completing normal package
installation, including the evaluation package's initialization utility; see
VENDOR_ACCESS.md.

Enable the optional profile after installing a legitimately licensed compiler:

```sh
cmake -S . -B build-matrix -DBERYL_COMPILER_MATRIX=ON \
  -DBERYL_IBM_COBOL_EXECUTABLE=/opt/ibm/cobol/1.2.0/bin/cob2 \
  -DBERYL_IBM_SCU_EXECUTABLE=/opt/ibm/cobol/1.2.0/bin/scu
cmake --build build-matrix --parallel
ctest --test-dir build-matrix -L ibm_linux --output-on-failure
```

The adapter copies/formats each free-format source using IBM's own
`scu -f -N -E` and captures its formatted stdout. Initial-formatting mode `-N`
avoids scu's statement/semantic conversion passes. `cob2 -q64
-qsrcformat(extend)` compiles the formatted copies, including generated-driver
lines longer than 72 columns. Originals remain unchanged. The driver stores its
internal return status in `PIC S9(9) COMP-5`; IBM rejects the prior BINARY-LONG
spelling. The independent vector fixture uses a simple DISPLAY loop counter,
which does not alter the tested record layout.

The runtime profile defaults to `BERYL_MATRIX_ibm_linux_ENVIRONMENT=COBRTOPT=FS=QSAM`.
IBM's [QSAM fixed-length file format](https://www.ibm.com/docs/en/cobol-linux-x86/1.2?topic=systems-qsam-file-system)
has no metadata, matching these raw fixed-record fixtures. Its default STL
selection rejected the raw input file with status 37. This is explicit runtime
configuration, not automatic file-format detection or support for QSAM variable
records/RDWs.

The exact unsigned packed-decimal vector test selects **C** sign nibbles to
match IBM's emitted bytes. Beryl's new `--unsigned-packed-sign c` option provides
that representation for generated/mutated/simplified records. Default unsigned
output remains F; the decoder accepts C/F for unsigned values and still rejects
negative signs in unsigned fields. See RECORD_LAYOUTS.md.

This validates Linux x86 fixture behavior only. IBM Enterprise COBOL on z/OS,
EBCDIC, mainframe data-set allocation and platform process control remain
unvalidated. This WSL host is also outside the specific Ubuntu releases listed
on IBM's product page; results do not establish vendor-certified host support.

Final local results on 2026-10-29: **48/48 suites passed without skips** in the
C17 Debug `-Werror` build (34.66 s), and **48/48 passed without skips** with
ASan/UBSan and `-Werror` (53.17 s), with no sanitizer findings. These counts
include all 44 earlier suites plus IBM's four actual-compiler suites. The
sanitizers instrument Beryl and its C assertion programs, not IBM's proprietary
compiler/runtime or the other external runtimes. Remote CI is not asserted.

## Rocket Visual COBOL for Eclipse Personal Edition

The optional `rocket` profile uses the user-supplied Ubuntu 11.0 distribution,
whose native compiler reports **11.0.0.84, 64-bit**. Install the product and its
license separately before configuring Beryl; CMake never installs or activates
proprietary software. The user confirmed that the intended non-commercial use
had been checked with a professional; see VENDOR_ACCESS.md for local setup.

```sh
cmake -S . -B build-matrix -DBERYL_COMPILER_MATRIX=ON \
  -DBERYL_ROCKET_COBOL_EXECUTABLE=/opt/rocketsoftware/VisualCOBOL/bin/cob \
  '-DBERYL_MATRIX_rocket_ENVIRONMENT=COBDIR=/opt/rocketsoftware/VisualCOBOL;PATH=/opt/rocketsoftware/VisualCOBOL/bin:/usr/bin:/bin;LD_LIBRARY_PATH=/opt/rocketsoftware/VisualCOBOL/lib'
cmake --build build-matrix --parallel
ctest --test-dir build-matrix -L rocket --output-on-failure
```

The profile compiles the unchanged fixtures and generated driver with
`cob -x -C 'sourceformat(free)'`. The four existing native integration suites
verify raw fixed SEQUENTIAL output, archived replay and deliberate boundary
regressions; exact signed DISPLAY and signed/unsigned packed vectors; 100 valid
generated records and byte-for-byte echo; and explicit BY REFERENCE calls with
return status 7 and extra-record rejection. Default unsigned packed sign F
matches this tested Rocket configuration. No oracle normalization or fixture
changes were required. These small local fixtures do not establish complete
language coverage, a redistributable runtime, or vendor-certified WSL support.
COPY preprocessing and mapped-line coverage remain GnuCOBOL-specific adapters.

On 2026-10-29 the complete C17 `-Werror` matrix passed **52/52 suites without
skips** in Debug (39.11 s) and **52/52 without skips** under ASan/UBSan
(73.57 s), with no sanitizer findings. All 48 previous suites remain enabled;
the four Rocket suites passed in each build. Sanitizers instrument Beryl and
its C assertion programs, not the external compiler/runtime binaries. Results
are from local execution; no remote CI result is asserted.
